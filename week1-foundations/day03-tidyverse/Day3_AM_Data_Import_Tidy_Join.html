1 Overview

By the end of this session you will be able to:

  • Read CSV, Excel, and other file formats into R
  • Understand what “tidy data” means and why it matters
  • Pivot data between wide and long formats using pivot_longer() and pivot_wider()
  • Separate and unite columns
  • Understand explicit vs. implicit missing values
  • Join two data frames together using mutating and filtering joins

2 Importing Data

2.1 Key Terms

Before reading data into R, three concepts matter:

  • Header: The first row of a file is usually variable names. R needs to know whether to treat it as names or as data values.
  • Delimiter: The character that separates entries in each row (comma in .csv, tab in .tsv, etc.). R uses this to know where one value ends and the next begins.
  • Missing value: How your file represents missingness. R recognizes NA, but files often use ., "", N/A, 999, or other codes that need to be declared.

2.2 Reading CSV Files with readr

library(tidyverse)  # loads readr
library(readxl)     # for Excel files
library(haven)      # for SAS, Stata, SPSS files

readr is the tidyverse package for reading rectangular data. The most common functions:

Function Reads
read_csv() Comma-separated (.csv)
read_csv2() Semicolon-separated (common in Europe)
read_tsv() Tab-separated
read_delim() Any delimiter you specify

All have the same interface — once you know read_csv() the rest are trivial.

2.3 Working Directories and File Paths

R looks for files relative to the working directory. Check yours with getwd():

getwd()
[1] "/Users/mclainfamily/Library/CloudStorage/OneDrive-UniversityofSouthCarolina/Teaching/Summer Workshop/INBRE-Bios-Summer-26/week1-foundations/day03-tidyverse"

Rather than hard-coding a full file path (which breaks on other people’s machines), use rstudioapi or this.path to set the working directory to wherever the script lives. Note, rstudioapi only works inside of RStudio and can give error messages when used with .qmd files (and in other situations). this.path is usually safer.

library(rstudioapi)
this.dir <- dirname(rstudioapi::getSourceEditorContext()$path)
setwd(this.dir)

library(this.path) 
this.dir <- this.dir()
setwd(this.dir)

Then reference files with short relative paths: "data/myfile.csv" rather than "/Users/yourname/Documents/.../myfile.csv".

You can use "../data/framingham.csv" to tell R to go back one folder, find the data folder, and then look for framingham.csv. We used this in the previous lab with:

framingham <- read_csv("../../data/framingham.csv")

which said go back two folders, find the data folder, and then look for framingham.csv.

Tip

Windows users: File paths use \ in Windows Explorer, but R requires / or \\. Copy a path from Explorer and replace each \ with / before using it in R.

2.4 Reading a CSV

students <- read_csv("data/students.csv")

When you run read_csv() it prints a message showing the number of rows and columns, the delimiter used, and how each column was parsed. This is useful for catching problems early.

2.4.1 Common Arguments

Skipping rows — useful when files have metadata at the top:

read_csv("The first line of metadata
  The second line of metadata
  x,y,z
  1,2,3", skip = 2)
# A tibble: 1 × 3
      x     y     z
  <dbl> <dbl> <dbl>
1     1     2     3

No column names — tell R to generate them:

read_csv("1,2,3
         4,5,6", col_names = FALSE)
# A tibble: 2 × 3
     X1    X2    X3
  <dbl> <dbl> <dbl>
1     1     2     3
2     4     5     6

Supply your own column names:

read_csv("1,2,3
         4,5,6", col_names = c("id", "weight", "height"))
# A tibble: 2 × 3
     id weight height
  <dbl>  <dbl>  <dbl>
1     1      2      3
2     4      5      6

Declare missing value codes — files often use . or N/A instead of NA:

read_csv("a,b,c
         1,2,.", na = ".")
# A tibble: 1 × 3
      a     b c    
  <dbl> <dbl> <lgl>
1     1     2 NA

2.4.2 Post-Import Cleaning

After reading data in, two immediate tasks often arise:

1. Fix column names with spaces. Column names with spaces require backtick quoting (\Full Name`) which is error-prone. Usejanitor::clean_names()` to convert everything to snake_case automatically:

library(janitor)
x <- data.frame(caseID = 1, DOB = 2, Other = 3)
x |> 
  clean_names()
  case_id dob other
1       1   2     3
# if you prefer camelCase variable names:
x %>%
  clean_names(., "lower_camel")
  caseId dob other
1      1   2     3

Or rename specific columns with rename():

x |> rename(case_id = `caseID`, dob = DOB, other = Other)
  case_id dob other
1       1   2     3

2. Fix variable types. read_csv() guesses column types from the data. Always check with str() and correct anything that was misread (e.g., a numeric column read as character because of a stray word like "five").

2.5 Reading Excel Files

Use readxl::read_excel(). You can specify which sheet to read:

library(readxl)
data_xl <- read_excel("data/myfile.xlsx", sheet = "data")
dict_xl <- read_excel("data/myfile.xlsx", sheet = "dictionary")

The same arguments apply: col_names, na, skip.

2.6 Writing Data

write_csv(students, "data/students_clean.csv")
Note

Important: When you write a tibble to CSV and read it back, factor levels and other type information are lost — the file only stores plain text. If you need to preserve types across sessions, use saveRDS() / readRDS() to save as an R binary file instead.

2.7 Other Formats

The haven package reads SAS (.sas7bdat), Stata (.dta), and SPSS (.sav) files with the same interface:

library(haven)
spss_data <- read_sav("data/myfile.sav") #SPSS data
sas_data  <- read_sas("data/myfile.sas7bdat") #SAS data
stata_data <- read_dta("data/myfile.dta") #Stata data

SPSS and Stata files often carry variable labels and value labels that haven preserves as attributes — useful when you are handed someone else’s data and need to understand the coding.

Tip

You can read in SAS data, you can even write SAS data (using write_sas), but SAS data exported from R will not properly be read into SAS. Exported SPSS (write_sav) and Stata (write_dta) files can be read into their respected software programs.

SPSS data has particularly nice features:

library(haven)
x2 <- labelled_spss(
  1:10,
  c(Good = 1, Okay = 4, Bad = 8),
  na_range = c(9, Inf),
  label = "Quality rating"
)
x2

3 Tidy Data

3.1 What Does “Tidy” Mean?

The same underlying data can be represented in many different ways. Consider these four representations of the same TB case data:

# A tibble: 6 × 4

6 China        2000 213766 1280428583

# A tibble: 12 × 4

   <chr>       <dbl> <chr>           <dbl>

 8 Brazil       2000 population  174504898

10 China        1999 population 1272915272
11 China        2000 cases          213766
12 China        2000 population 1280428583
table3  # two variables crammed into one column
# A tibble: 6 × 3
  country      year rate             
  <chr>       <dbl> <chr>            
1 Afghanistan  1999 745/19987071     
2 Afghanistan  2000 2666/20595360    
3 Brazil       1999 37737/172006362

# A tibble: 3 × 3
  country     `1999` `2000`
  <chr>        <dbl>  <dbl>

2 Brazil       37737  80488
3 China       212258 213766
table4b # population only, years as columns
# A tibble: 3 × 3
  country         `1999`     `2000`
  <chr>            <dbl>      <dbl>
1 Afghanistan   19987071   20595360
2 Brazil       172006362  174504898
3 China       1272915272 1280428583

Only table1 is tidy. Tidy data follows three rules:

  1. Each variable is a column; each column is a variable
  2. Each observation is a row; each row is an observation
  3. Each value is a cell; each cell is a single value

Why tidy? Because every function in the tidyverse — ggplot2, dplyr, tidyr, modeling functions — expects tidy data. When your data is tidy, tools work naturally. When it is not, you spend your time fighting the data instead of analyzing it.

Here is how naturally table1 works once it is tidy:

# Compute rate per 10,000
table1 |>
  mutate(rate = cases / population * 10000)
# A tibble: 6 × 5
  country      year  cases population  rate
  <chr>       <dbl>  <dbl>      <dbl> <dbl>

3 Brazil       1999  37737  172006362 2.19 
4 Brazil       2000  80488  174504898 4.61 
5 China        1999 212258 1272915272 1.67 
6 China        2000 213766 1280428583 1.67

table1 |>
  count(year, wt = cases)
# A tibble: 2 × 2

1  1999 250740
2  2000 296920

3.4 Separating and Uniting Columns

3.4.1 Separating Columns

separate_wider_delim() splits a column on a delimiter character.

table3  # rate column contains "cases/population"
# A tibble: 6 × 3
  country      year rate             
  <chr>       <dbl> <chr>            
1 Afghanistan  1999 745/19987071     
2 Afghanistan  2000 2666/20595360    
3 Brazil       1999 37737/172006362  
4 Brazil       2000 80488/174504898  
5 China        1999 212258/1272915272
6 China        2000 213766/1280428583
table3 |>
  separate_wider_delim(rate, delim = "/", names = c("cases", "population"))
# A tibble: 6 × 4
  country      year cases  population
  <chr>       <dbl> <chr>  <chr>     
1 Afghanistan  1999 745    19987071  
2 Afghanistan  2000 2666   20595360  
3 Brazil       1999 37737  172006362 
4 Brazil       2000 80488  174504898 
5 China        1999 212258 1272915272
6 China        2000 213766 1280428583

The resulting columns are character by default. Pipe into mutate() to convert types after splitting:

table3 |>
  separate_wider_delim(rate, delim = "/", names = c("cases", "population")) |>
  mutate(cases = as.integer(cases), population = as.integer(population))
# A tibble: 6 × 4
  country      year  cases population
  <chr>       <dbl>  <int>      <int>
1 Afghanistan  1999    745   19987071
2 Afghanistan  2000   2666   20595360
3 Brazil       1999  37737  172006362
4 Brazil       2000  80488  174504898
5 China        1999 212258 1272915272
6 China        2000 213766 1280428583

separate_wider_position() splits at a fixed character position. Supply a named integer vector where the name becomes the column name and the integer is the field width. Unnamed entries are dropped silently:

# Split the 4-digit year into century (first 2 chars) and year (last 2 chars)
table3 |>
  separate_wider_position(year, widths = c(century = 2, year = 2))
# A tibble: 6 × 4
  country     century year  rate             
  <chr>       <chr>   <chr> <chr>            
1 Afghanistan 19      99    745/19987071     
2 Afghanistan 20      00    2666/20595360    
3 Brazil      19      99    37737/172006362  
4 Brazil      20      00    80488/174504898  
5 China       19      99    212258/1272915272
6 China       20      00    213766/1280428583

Combine both to split rate by delimiter and year by position in one pipeline:

table3 |>
  separate_wider_delim(rate, delim = "/", names = c("cases", "population")) |>
  mutate(cases = as.integer(cases), population = as.integer(population)) |>
  separate_wider_position(year, widths = c(century = 2, year = 2))
# A tibble: 6 × 5
  country     century year   cases population
  <chr>       <chr>   <chr>  <int>      <int>

4 Brazil      20      00     80488  174504898

6 China       20      00    213766 1280428583

# Rebuild the year column from century + year

3.5 Missing Values: Explicit vs. Implicit

A value can be missing in two distinct ways:

  • Explicit: the cell exists and contains NA
  • Implicit: the row simply does not exist in the data
stocks <- tibble(
  year   = c(2015, 2015, 2015, 2015, 2016, 2016, 2016),
  qtr    = c(   1,    2,    3,    4,    2,    3,    4),
  return = c(1.88, 0.59, 0.35,   NA, 0.92, 0.17, 2.66)
)
stocks
# A tibble: 7 × 3
   year   qtr return
  <dbl> <dbl>  <dbl>
1  2015     1   1.88
2  2015     2   0.59
3  2015     3   0.35
4  2015     4  NA   
5  2016     2   0.92
6  2016     3   0.17
7  2016     4   2.66

The return for Q4 2015 is explicitly missing (NA). The return for Q1 2016 is implicitly missing — the row does not exist at all.

Pivoting can make implicit missings explicit:

stocks |>
  pivot_wider(names_from = year, values_from = return)
# A tibble: 4 × 3
    qtr `2015` `2016`
  <dbl>  <dbl>  <dbl>
1     1   1.88  NA   
2     2   0.59   0.92
3     3   0.35   0.17
4     4  NA      2.66

Use complete() to make implicit missing values explicit while keeping long format:

stocks |>
  complete(year, qtr)
# A tibble: 8 × 3
   year   qtr return
  <dbl> <dbl>  <dbl>
1  2015     1   1.88
2  2015     2   0.59
3  2015     3   0.35
4  2015     4  NA   
5  2016     1  NA   
6  2016     2   0.92
7  2016     3   0.17
8  2016     4   2.66

Use fill() when missing values mean “same as the previous row” (last observation carried forward):

treatment <- tribble(
  ~person,            ~treatment, ~response,
  "Derrick Whitmore", 1,          7,
  NA,                 2,          10,
  NA,                 3,          9,
  "Katherine Burke",  1,          4
)

treatment |> fill(person)
# A tibble: 4 × 3
  person           treatment response
  <chr>                <dbl>    <dbl>
1 Derrick Whitmore         1        7
2 Derrick Whitmore         2       10
3 Derrick Whitmore         3        9
4 Katherine Burke          1        4

4 Joining Data

4.1 Why Join?

It is rare that all the information you need lives in a single data frame. Relational data — data spread across multiple linked tables — is the norm in practice. Joins let you combine them.

We will use the nycflights13 package, which has five related tables:

library(nycflights13)
  • flights: every flight departing NYC in 2013
  • airlines: carrier codes and full names
  • airports: airport codes and metadata
  • planes: plane metadata by tail number
  • weather: hourly weather at each NYC airport

4.3.3 Other Mutating Joins

Join Keeps
left_join(x, y) All rows of x; fills NAs where no match in y
right_join(x, y) All rows of y; fills NAs where no match in x
inner_join(x, y) Only rows with matches in both x and y
full_join(x, y) All rows from both; NAs where no match on either side

In practice: use left_join() as your default. Use inner_join() only when you explicitly want to drop non-matching rows and have verified that is safe.

4.4 Filtering Joins

Filtering joins do not add columns — they use y to decide which rows of x to keep or drop.

4.4.1 semi_join() — keep rows in x that have a match in y

# Keep only airports that appear as origins in flights
airports |>
  semi_join(flights2, by = c("faa" = "origin"))

4.4.2 anti_join() — keep rows in x that have NO match in y

anti_join() is the most useful diagnostic tool for join problems. It finds rows that would be silently dropped by an inner join.

# Which destination codes in flights have no matching airport entry?
flights2 |>
  anti_join(airports, by = c("dest" = "faa")) |>
  distinct(dest)
# A tibble: 4 × 1
  dest 
  <chr>
1 BQN  
2 SJU  
3 STT  
4 PSE  
# Which tail numbers in flights have no plane record?
flights2 |>
  anti_join(planes, by = "tailnum") |>
  distinct(tailnum) |>
  nrow()
[1] 722
Tip

Always run anti_join() before a major join. If it returns rows you did not expect to drop, you have a data quality problem to investigate before proceeding with the analysis.
