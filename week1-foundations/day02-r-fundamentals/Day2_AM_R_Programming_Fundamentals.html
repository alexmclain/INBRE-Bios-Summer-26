1 Overview

By the end of this session you will be able to:

  • Recognize the main object types in R and know when each arises
  • Understand the variable types you will encounter in biological datasets
  • Manipulate and transform data using core dplyr verbs
  • Understand what a function is and read a simple one

2 Object Types in R: A Quick Tour

R has several object types. We will cover them briefly here because you will see them mentioned in help files and error messages. In practice, you will almost always be working with tibbles (see below), so don’t worry about memorizing these — just know they exist.

2.1 Vectors

A vector is the simplest object: a sequence of values all of the same type. Everything else in R is built on top of vectors.

nums <- c(1.5, 2.3, 7.1, 4.8)
chars <- c("control", "treatment", "control", "treatment")
logicals <- c(TRUE, FALSE, TRUE, TRUE)

2.2 Matrices

A matrix is a 2D vector — all values must be the same type. Useful for linear algebra, but rarely used to store biological data directly.

m <- matrix(1:9, nrow = 3, ncol = 3)
m
     [,1] [,2] [,3]
[1,]    1    4    7
[2,]    2    5    8
[3,]    3    6    9

2.3 Lists

A list is a collection of objects that can be of different types and lengths — think of it as a container that can hold anything. Model output in R (e.g., from lm()) is returned as a list.

my_list <- list(
  name   = "Patient A",
  values = c(1.2, 3.4, 5.6),
  flag   = TRUE
)
my_list
$name
[1] "Patient A"

$values
[1] 1.2 3.4 5.6

$flag
[1] TRUE
my_list$name
[1] "Patient A"
my_list$values
[1] 1.2 3.4 5.6

2.4 Data Frames and Tibbles

A data frame is a rectangular table where each column is a vector. A tibble is the tidyverse version of a data frame with some sensible defaults: it prints more neatly, never converts strings to factors automatically, and gives cleaner error messages.

Important

This is the object type you will use for virtually everything in this course. When you read in a dataset with readr (e.g., read_csv()), you get a tibble. When you manipulate data with dplyr, you get a tibble back. You will rarely need to think about matrices or bare lists for your data. However, R functions will commonly give back results as lists. So, knowing how to work with them is important.

# A small tibble created by hand
patient_data <- tibble(
  id        = 1:5,
  treatment = c("A", "B", "A", "B", "A"),
  response  = c(12.1, 8.4, 14.3, 9.1, 11.7)
)
patient_data
# A tibble: 5 × 3
     id treatment response
  <int> <chr>        <dbl>
1     1 A             12.1
2     2 B              8.4
3     3 A             14.3
4     4 B              9.1
5     5 A             11.7

Notice what prints above the column values: <int>, <chr>, <dbl>. These are the variable types, which we cover next.

3 Indexing in R

Indexing means extracting specific elements from an object — a single value, a column, a row, or a subset. Knowing how to do this in base R is important because you will encounter it constantly in help files, Stack Overflow answers, and other people’s code, even if you end up preferring tidyverse syntax for most tasks.

3.1 Indexing Vectors with [ ]

Use single square brackets to extract elements from a vector by position:

x <- c(10, 20, 30, 40, 50)

x[1]        # first element (R is 1-indexed, not 0-indexed)
[1] 10
x[3]        # third element
[1] 30
x[c(1, 3)]  # first and third elements
[1] 10 30
x[2:4]      # elements 2 through 4
[1] 20 30 40
x[-1]       # everything except the first element
[1] 20 30 40 50

You can also index by a logical vector of the same length. Elements where the condition is TRUE are kept:

x[x > 25]           # elements greater than 25
[1] 30 40 50
x[c(TRUE, FALSE, TRUE, FALSE, TRUE)]  # explicit logical index
[1] 10 30 50

Named vectors can be indexed by name:

bp <- c(systolic = 120, diastolic = 80)
bp["systolic"]
systolic 
     120 
bp[c("systolic", "diastolic")]
 systolic diastolic 
      120        80

3.2 Indexing Data Frames with [ , ]

Data frames use two-dimensional indexing: [rows, columns]. Leaving one dimension blank means “all”:

patient_data <- data.frame(
  id        = 1:5,
  treatment = c("A", "B", "A", "B", "A"),
  response  = c(12.1, 8.4, 14.3, 9.1, 11.7)
)

patient_data[1, ]        # first row, all columns
  id treatment response
1  1         A     12.1
patient_data[, 2]        # all rows, second column (returns a vector)
[1] "A" "B" "A" "B" "A"
patient_data[1, 2]       # first row, second column (single value)
[1] "A"
patient_data[1:3, ]      # rows 1 through 3
  id treatment response
1  1         A     12.1
2  2         B      8.4
3  3         A     14.3
patient_data[, c(1, 3)]  # columns 1 and 3
  id response
1  1     12.1
2  2      8.4
3  3     14.3
4  4      9.1
5  5     11.7

Columns can also be referenced by name inside [ ]:

patient_data[, "response"]
[1] 12.1  8.4 14.3  9.1 11.7
patient_data[patient_data$treatment == "A", ]  # rows where treatment is "A"
  id treatment response
1  1         A     12.1
3  3         A     14.3
5  5         A     11.7

3.3 The $ Operator

$ is the most common way to extract a single column from a data frame or element from a list. It returns the column as a vector:

patient_data$response        # the response column as a vector
[1] 12.1  8.4 14.3  9.1 11.7
patient_data$treatment       # the treatment column as a vector
[1] "A" "B" "A" "B" "A"
mean(patient_data$response)  # pass directly to a function
[1] 11.12
Tip

In RStudio, typing patient_data$ will trigger autocomplete showing all available column names. This is one of the most useful features of the IDE for data exploration.

$ works identically on lists:

my_list <- list(name = "Patient A", values = c(1.2, 3.4, 5.6))
my_list$name
[1] "Patient A"
my_list$values[2]  # chain indexing: second element of the values vector
[1] 3.4

3.4 Double Brackets [[ ]]

Double brackets extract a single element by position or name, stripping the container. The difference from $ is subtle but matters for lists and programmatic access:

patient_data[["response"]]   # same result as patient_data$response
[1] 12.1  8.4 14.3  9.1 11.7
my_list[["values"]]          # same as my_list$values
[1] 1.2 3.4 5.6
# Useful when the column name is stored in a variable
col_name <- "response"
patient_data[[col_name]]     # $ does not work here; [[ ]] does
[1] 12.1  8.4 14.3  9.1 11.7

3.5 Putting It Together: Subsetting a Data Frame

A common task is extracting a subset of rows and columns based on a condition:

# Patients in treatment A with response above 12
patient_data[patient_data$treatment == "A" & patient_data$response > 12, ]
  id treatment response
1  1         A     12.1
3  3         A     14.3
Note

This base R approach is verbose but important to recognize. In the next section we will use dplyr::filter() and dplyr::select() to do the same thing more readably. Both approaches are valid — you will see both in the wild.

3.6 Quick Reference

Goal Syntax
Vector element by position x[2]
Vector elements by condition x[x > 5]
Data frame column as vector df$col or df[["col"]]
Data frame rows by condition df[df$col == "A", ]
Data frame single cell df[2, 3]
List element lst$name or lst[["name"]]

4.1 Numeric Variables (<dbl>, <int>)

Numeric variables represent measured quantities. Arithmetic and summary functions apply directly.

mean(flights$dep_delay, na.rm = TRUE)
[1] 12.63907
sd(flights$dep_delay, na.rm = TRUE)
[1] 40.21006
range(flights$air_time, na.rm = TRUE)
[1]  20 695
Note

na.rm = TRUE tells R to ignore missing values when computing the summary. Without it, a single NA in the vector will return NA for the whole calculation.

4.2 Character Variables (<chr>)

Character variables (strings) hold text. They cannot be used in arithmetic but can be searched, split, and recoded.

# How many unique carriers are there?

[16] "OO"
# How many flights per carrier?
table(flights$carrier)

   9E    AA    AS    B6    DL    EV    F9    FL    HA    MQ    OO    UA    US

   VX    WN    YV

Common string operations from stringr (all start with str_):

x <- c("Control Group", "Treatment Group A", "Treatment Group B")

str_to_lower(x)          # convert to lowercase
[1] "control group"     "treatment group a" "treatment group b"
str_to_upper(x)          # convert to uppercase
[1] "CONTROL GROUP"     "TREATMENT GROUP A" "TREATMENT GROUP B"
str_length(x)            # number of characters
[1] 13 17 17
str_detect(x, "Control") # does the string contain "Control"?
[1]  TRUE FALSE FALSE
str_replace(x, "Group", "Arm") # replace a pattern
[1] "Control Arm"     "Treatment Arm A" "Treatment Arm B"

str_detect() is especially useful for filtering:

# Keep only carriers whose code starts with "U"
table(str_detect(flights$carrier, "^U"))

 FALSE   TRUE 
257575  79201

4.3 Logical Variables (<lgl>)

Logicals are TRUE or FALSE. They arise naturally from comparisons and are useful for filtering and counting.

# Create a logical variable: was the flight delayed on arrival?
table(flights$arr_delay > 0)

 FALSE   TRUE 
194342 133004

sum() and mean() treat TRUE as 1 and FALSE as 0, so you can count and compute proportions easily:

sum(flights$arr_delay > 0, na.rm = TRUE)
[1] 133004
mean(flights$arr_delay > 0, na.rm = TRUE)*100
[1] 40.63101

4.4 Factors (<fct>)

Factors represent categorical variables with a fixed set of levels. They are essential in statistical modeling — a factor in a regression model is handled as a categorical predictor (with a reference level), while a character variable or numeric code is not.

# Create a factor
severity <- factor(c("mild", "severe", "moderate", "mild", "severe"),
                   levels = c("mild", "moderate", "severe"))
severity
[1] mild     severe   moderate mild     severe  
Levels: mild moderate severe
levels(severity)
[1] "mild"     "moderate" "severe"  
table(severity)
severity
    mild moderate   severe 
       2        1        2
Important

When does this matter for you? If you code a categorical variable as a number (e.g., 1 = mild, 2 = moderate, 3 = severe) and put it in a model without converting it to a factor, R will treat it as a continuous variable and fit a single slope. This is almost never what you want. Always check whether your grouping variables are stored as factors. This is one of the most common errors when running models in R.

Use factor() to convert, and fct_recode() from the forcats package (part of the tidyverse) to rename levels:

flights$origin_fct = factor(flights$origin)
flights$origin_fct[1:5]
[1] EWR LGA JFK JFK LGA
Levels: EWR JFK LGA

The first level is the reference level, to change use relevel (important for model interpretation):

severity_reref <- relevel(severity, ref = "moderate")
levels(severity_reref)
[1] "moderate" "mild"     "severe"

4.4.1 Recoding and Collapsing Levels

fct_recode() lets you rename levels; fct_collapse() merges them:

severity_recoded <- fct_recode(severity,
  "Grade 1" = "mild",
  "Grade 2" = "moderate",
  "Grade 3" = "severe"
)
levels(severity_recoded)
[1] "Grade 1" "Grade 2" "Grade 3"
# Collapse moderate and severe into a single "high" level
fct_collapse(severity,
  "low"  = "mild",
  "high" = c("moderate", "severe")
)
[1] low  high high low  high
Levels: low high

5 Data Transformations with dplyr

dplyr is the workhorse package for data manipulation. Its functions are called verbs because each one does one thing clearly. We will cover the ones you will use in almost every analysis.

5.1 The Pipe

The pipe (|>) passes the output of one function as the first argument of the next. Read it as “then”:

flights |>           # start with flights, then
  filter(...) |>     # keep certain rows, then
  mutate(...) |>     # create new columns, then
  summarize(...)     # collapse to a summary

You may also see %>% from the magrittr package — it behaves identically for our purposes.

5.5 Recoding Variables: if_else() and case_when()

Two functions come up constantly when creating new variables inside mutate().

if_else() handles a simple two-way recode:

flights |>
  mutate(long_flight = if_else(air_time > 300, "Long", "Short")) |>
  count(long_flight)
# A tibble: 3 × 2
  long_flight      n
  <chr>        <int>
1 Long         43654
2 Short       283692
3 <NA>          9430

case_when() handles three or more conditions. Each condition is written as condition ~ value, and .default catches anything not matched:

flights |>
  mutate(
    delay_category = case_when(
      dep_delay <= 0          ~ "On time or early",
      dep_delay <= 30         ~ "Minor delay (<= 30 min)",
      dep_delay <= 120        ~ "Moderate delay (31-120 min)",
      .default                = "Major delay (> 120 min)"
    )
  ) |>
  count(delay_category)

6 Introduction to Functions

6.1 What Is a Function?

You have been using functions since Day 1: mean(), filter(), mutate(). A function is a reusable block of code that takes inputs (arguments) and returns an output.

Writing your own functions becomes valuable once you find yourself copying and pasting the same block of code more than twice. Instead of repeating code — and risking subtle errors each time — you write it once, name it, and call it.

Note

You will not be writing many functions in this workshop. The goal here is to understand the concept so that you can read functions when you encounter them and recognize when your own code might benefit from one eventually.

6.2 Function Anatomy

Every function has three parts:

my_function <- function(argument1, argument2) {
  # body: code that uses the arguments
  result <- argument1 + argument2
  result   # the last evaluated expression is returned
}

A simple example — a function that converts Fahrenheit to Celsius:

f_to_c <- function(fahrenheit) {
  (fahrenheit - 32) * 5 / 9
}

f_to_c(98.6)   # normal body temperature
[1] 37
f_to_c(212)    # boiling point of water
[1] 100
f_to_c(c(32, 72, 98.6, 104))  # works on a vector too
[1]  0.00000 22.22222 37.00000 40.00000

6.3 Default Arguments

Functions can have default values for arguments. The caller only needs to supply a value if they want to override the default:

round_to <- function(x, digits = 2) {
  round(x, digits)
}

round_to(3.14159)       # uses the default: 2 digits
[1] 3.14
round_to(3.14159, 4)    # override to 4 digits
[1] 3.1416

6.4 A Practical Example: A Custom Summary

Imagine you are computing the same set of summaries repeatedly on different variables. Rather than typing it out each time, you can wrap it in a function:

quick_summary <- function(x) {
  tibble(
    n       = sum(!is.na(x)),
    n_miss  = sum(is.na(x)),
    mean    = mean(x, na.rm = TRUE),
    sd      = sd(x, na.rm = TRUE),
    min     = min(x, na.rm = TRUE),
    max     = max(x, na.rm = TRUE)
  )
}

quick_summary(flights$dep_delay)
# A tibble: 1 × 6
       n n_miss  mean    sd   min   max
   <int>  <int> <dbl> <dbl> <dbl> <dbl>
1 328521   8255  12.6  40.2   -43  1301
quick_summary(flights$air_time)
# A tibble: 1 × 6
       n n_miss  mean    sd   min   max
   <int>  <int> <dbl> <dbl> <dbl> <dbl>
1 327346   9430  151.  93.7    20   695

The same code, applied to any numeric vector, with one function call. This is the core benefit: write once, use many times, update in one place.

6.5 When to Write a Function

A useful rule of thumb: if you have copied and pasted a block of code three times, it is time to write a function. The benefits are:

  1. Readability — a well-named function makes code self-documenting
  2. Maintainability — one change propagates everywhere
  3. Fewer errors — no risk of updating a value in one copy but not another

For now, focus on reading and understanding functions when you encounter them. As you get more comfortable with R, writing your own will start to feel natural.
